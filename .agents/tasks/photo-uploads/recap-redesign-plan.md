## Decisions

1. **Figures are required numbers, not optional.** `totalCompletionsCount`, `totalRatingsCount`, `parksExploredCount` are `readonly number` on `TripRecapFiguresDTO`; the projection defaults an absent summary total to `0` (documented in the spec). Required keys make the exact-key-set test deterministic and let the screen render without `??`.
2. **`parksExploredCount = new Set((summary.parkBreakdown ?? []).map((p) => p.park)).size`** (distinct parks, robust even if a breakdown ever repeats a park). `TripSummaryScreen` uses `parkBreakdown?.length ?? 0`; for the real summary the two are equal.
3. **Top-rated catalog fields are optional and omitted when null/undefined**: `park?: Park`, `category?: string`, `imageUrl?: string` (JSON-shaped, `Park` imported from `@dwt/shared`). The projection includes a key only when the source value is neither `undefined` nor `null`, via conditional spreads; `experienceId` is never copied. Extract the inline row type to an exported `TripRecapTopRatedDTO` (re-exported in both index files).
4. **Allowed key lists (the contract the tests pin):**
   - figures: `distinctExperienceCount, parksExploredCount, plannedCompletedCount, plannedTotalCount, superlatives, topRated, totalCompletionsCount, totalRatingsCount` (sorted).
   - top-rated row: `category, experienceName, imageUrl, meanRating, park, ratingCount` (sorted; `park/category/imageUrl` present only when the source has them).
   - superlative: unchanged (`id, title, description, icon, experienceName?, value?, memberDisplayName?`, D26).
5. **Shared presentational components live in `apps/mobile/src/screens/trips/summary/`**, next to the screen they were lifted from, and keep using `../TripSummaryScreen.palette` (no new palette file; if a genuinely new one-off colour is needed, add `summary/SummaryComponents.palette.ts` with `definePalette({light, dark})`). Style objects are moved verbatim (same `theme.spacing/radius/typography` statics, same `withAlpha`, same palette reads) so the Summary render stays identical. Added a11y props (`accessibilityRole="header"` on section titles and hero title, `accessible`/`accessibilityLabel` on the rating pill, decorative icon discs hidden) are non-visual; if any of them breaks an existing `TripSummaryScreen` test, make that prop opt-in rather than editing the test.
6. **Copy**: recap hero pill `Shared by <sharerDisplayName>` (fallback `Shared recap` when the name is empty, because the route returns `''` when unknown); empty-plan line exported as `RECAP_NO_PLAN_COPY = 'No planned itinerary on this trip.'`; award section title and top-rated section title identical to the Summary (`Group Superlatives & Awards`, `Top-Rated Moments`). The tile label singular rule (`Distinct Ride` when the count is 1) comes along with the shared tile; tests account for it.
7. **No Member Contributions anywhere** in the recap: not in the screen, not the DTO, not any fixture expectation. The screen file must not contain the strings `perMember`, `memberId`, `Member Contributions` (pinned by a source-guard test).
