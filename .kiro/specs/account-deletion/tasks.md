Run the scoped `verify:shared` / `verify:api` / `verify:mobile` once at each checkpoint. Run the full `npm run verify` once, at task 18, and never as a substitute for the per-behavior assertions. A vitest or jest run alone is not the gate because it does not typecheck. Never lower or exclude the coverage threshold.
- **Test discipline.** Tests ship in the same task as the code. Property tests use `fast-check` with at least 100 runs and the tag `// Feature: account-deletion, Property N: <text>`. Every repo path has a pg-mem test that reads rows back; a bug fix needs a test at the layer where the defect lived. Mobile tests render the real component and mock only the network or query layer, drive each interaction, and assert both the call (endpoint and payload) and the on-screen result.
- **Real paths that differ from the design's wording.** `LoginScreen.tsx` is `apps/mobile/src/screens/LoginScreen.tsx` (there is no `screens/auth` folder). The mobile `hooks/` folder exists and there is no `lib/` folder; do not create one.
- **Fixture blast radius.** Adding the required `AppConfig.accountDeletion` namespace breaks `tsc` in every full-`AppConfig` test literal. Task 2.2 owns them all; `npm run typecheck` in `apps/api` is where a missed one shows.
- **Guards are the safety net, per-surface tests are the proof.** The visibility and roster guards stop new unsafe reads but do not prove existing ones were converted. Convert the surface table row by row with a pg-mem test for each. Pinned guard counts come from the guard's report on the finished tree.
- **pg-mem limits.** pg-mem has no `jsonb_set` or `to_jsonb` (JSONB scrubbing is TypeScript), is single-connection (true `SKIP LOCKED` and lock interaction are argued, not executed), and is lenient about parameter typing. Fallbacks for the `id::text LIKE` CHECK, `id = ANY(ARRAY(...))`, `Date` parameters in the claim and data-modifying CTEs are recorded in the design; the operator smoke list (task 19.3) covers what pg-mem cannot.
- **What a green run does and does not prove.** `npm run verify` proves nothing is broken, not that new behavior is covered; the behavior-to-test map in task 18 is the check for executed-but-unasserted code. Cron schedules, Render cold starts and Neon behavior under load are not exercised by any test here.
- **Accepted limitations (documented, not worked around).** A lost response to `POST /me/account/deletion` leaves the user signed out with no on-screen date (the email is the record, R1.15). Pending-member expenses are read-only until restore or forever after purge, though deletable. A pending sender's shared trip recap is unavailable. Tombstone and retained `experience_logs` rows accumulate unreaped. The existing `ChangePasswordControl` `401` defect is out of scope.
