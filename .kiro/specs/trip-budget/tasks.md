## Overview

This plan builds the Trip Budget feature and the supporting pieces specified in `design.md`: shared contracts and a shared menu price parser; four migrations; structured menu prices with lazy refill; Lightning Lane price persistence extracted from the park schedule responses the sampler already fetches (no extra request); a demand-driven, kill-switched, circuit-broken Disney ticket price cache; permissions and account-deletion entries; an admin diagnostic page; the pure Budget modules; the Budget repo and routes; and the mobile Budget screens plus the shared Menu Item Picker (also used by Expenses).

Tests ship in the same task as the code they cover. Pure modules get unit tests plus `fast-check` property tests (at least 100 runs, tagged `// Feature: trip-budget, Property N: <title>`); routes get `server.inject` tests (auth gate, happy path, validation); repos get tests that run the real SQL (`pg-mem` for the Budget repo's plain single-array SQL; `*.livedb.test.ts` against a local Postgres for `ticketPrices/repo.ts` and the Lightning Lane writers, because pg-mem cannot run multi-array `unnest`, tuple `IS DISTINCT FROM`, `make_interval`, error `21000` or concurrent claims; the executor runs those once and pastes the output); migrations get `migrationNNNN.test.ts`; shared Zod schemas get valid and invalid cases; mobile components get `@testing-library/react-native` interaction tests under `jest-expo` (never Vitest) that assert both the network call and the on-screen change.

Verification tiers (from `.kiro/steering/execution-discipline.md`): while iterating run only the single test file (`npx vitest run <path>` in api/shared, `npx jest <file>` in mobile) and `npm run typecheck` after type changes; run the scoped `npm run verify:shared|api|mobile` at checkpoints; run the full `npm run verify` **once**, at task 21. Paste the literal tail output and exit code, and produce the behavior-to-test map in the final report.
