## Overview

This plan builds Trip Lodging Stays as specified in `design.md`: the shared `tripStays.ts` module with the `effectiveStays` resolver; migration `0073` with a conservative backfill; the repo functions and the `PUT /trips/:id/stays` route with `trip_resorts` kept as a derived projection; the per-stay booking timeline; and the mobile hub card, edit section, Stay sheet, Live Glance name and booking-settings note.

Tests ship in the same task as the code they cover. Pure modules get unit tests plus `fast-check` property tests (at least 100 runs, tagged `// Feature: trip-lodging-stays, Property N: <title>`); routes get `server.inject` tests (auth gate, happy path, validation); the repo gets pg-mem tests that run the real SQL and read rows back; the migration gets `migration0073.test.ts`; shared Zod schemas get valid and invalid cases; mobile components get `@testing-library/react-native` interaction tests under `jest-expo` (never Vitest) that assert both the network call and the on-screen change.

Verification tiers (from `.kiro/steering/execution-discipline.md`): while iterating run only the single test file (`npx vitest run <path>` in api and shared, `npx jest <file>` in mobile) and `npm run typecheck` after type changes; run the scoped `npm run verify:shared|api|mobile` at checkpoints; run the full `npm run verify` **once**, at task 10. Paste the literal tail output and exit code, and produce the behavior-to-test map in the final report.

### Cross-spec dependencies and build order

## Notes

- **Verification discipline.** A green `vitest`/`jest` run is not the gate; only `npm run verify` (typecheck and tests across all workspaces) counts. Run it once, at task 10. While iterating, run only the single test file. On Windows, `npm run verify` takes several minutes and exceeds the tool output limit: capture it with `cmd /c "npm run verify > C:\path\out.txt 2>&1"`, read `$LASTEXITCODE`, then `Select-String` the file for `error TS`, `does not meet threshold`, `Test Files`, `Tests` and `Test Suites`. Never overlap two test runs.
- **Shared package.** `apps/api` reads `@dwt/shared` from `packages/shared/dist`. Run `npm run build:shared` after every shared change. A name missing from the explicit `index.ts` export lists is `undefined` at runtime in the API.
- **`trip_resorts` is a projection.** Never write it except through `rewriteTripResorts` (after a stay change) and the existing `replaceTripResorts` path that the legacy translation wraps. Every current reader keeps reading it unchanged.
- **The resolver is the only place that interprets stays.** Booking, the glance, the hub and the dining plan all call `effectiveStays`; no consumer may re-implement the legacy, gap or implicit rules.
- **Timeline identity.** The legacy code path in `timeline.ts` must stay logically untouched; Property 10 compares against a copy of the old derivation. Do not "tidy" it.
- **Hand-off dates are shared.** `[check_in, check_out)` ranges may not intersect; a shared boundary date is valid and is covered by both stays' date lists in the timeline (merged by window key).
- **Dates.** Calendar-date strings with UTC-midnight arithmetic only; never `new Date('YYYY-MM-DD')` in local time. node-pg may return `DATE` columns as `Date` objects: normalize to strings.
- **pg-mem limits.** pg-mem has no exclusion constraints and may lack `ROW_NUMBER() OVER`, `LATERAL` or date arithmetic: overlap is enforced in the repo under the Trip lock, and any SQL pg-mem cannot vouch for is run in a rolled-back transaction against the local Postgres before relying on it. Do not use `ON CONFLICT` against a partial unique index.
- **Account deletion.** `trip_stays` has no user foreign key (`party_keys` is plain text). If the account-deletion registry test fails, read why before adding a disposition entry.
- **Edit real source directly.** No codegen or string-replacement scripts, no stray files at the repo root. Wire consumers against the real exported types and typecheck right after wiring.
- **Mobile tests are Jest (`jest-expo`); api and shared tests are Vitest.** Do not cross them. Every new `.tsx` uses `makeStyles`/`useAppTheme`; one-off colours go in `*.palette.ts`; `themeRetrofit.guard.test.ts` must pass without extending its allowlist.
- **Out of scope** (do not build without a spec amendment): room types and room counts, lodging prices or budget lines (the Budget `lodging` category stays user-entered), booking or checking in anywhere, importing reservations from a Disney account, per-stay check-in times, a calendar view of stays, and notifications about stays.
